# Output formats

Choose the smallest useful output matching the user's request. The hard deliverable-type, substantive-change, and deletion gates in `SKILL.md` apply in every mode. Format choices do not expand editing authority.

## Modes

| Request | Appropriate output |
|---|---|
| General review or review-and-revise | Diagnosis first, with located findings and recommended treatment; an annotated copy when useful or requested. Wait for necessary material-change approvals before a clean revision. |
| Audit/evidence check only | Requested findings and best current judgments; no unrequested rewrite. |
| Annotated copy only | Preserve original text and add located comments; perform sufficient internal review without requiring extra user-facing files. |
| Direct rewrite | Full clean revision within existing authority. Isolate unresolved material changes or proposed deletions for approval; direct rewrite waives staging, not those gates. |
| Bounded language polish | Revised passage/file without a full diagnosis package; preserve propositions and coverage. Flag substantive issues separately without silently changing them. |
| Restructure proposal | Proposed outline and old-to-new map; this is an authorized proposal, not a completed rewritten report. |
| Already acceptable | State that no material change is necessary and preserve the source; do not invent findings or create another version merely to show work. |

For short pasted passages, chat may suffice. For substantial file-based work, preserve the editable source format when practical and use the appropriate artifact workflow. Do not create an issue report, evidence table, annotated copy, comparison, deletion register, and summary as separate files by default. Combine traceability information sensibly. A new executive summary is optional unless requested or needed in the report's established architecture.

## Located findings and decisions

For complex reviews, use a compact table with ID, severity, location, verdict, consequence, and recommended treatment. A separate logic/evidence table is useful only if it clarifies rather than duplicates the issue list. For short reviews, located prose or bullets are enough.

For every major issue, distinguish the supported portion from the invalid or overstated portion and state the corrected conclusion or treatment. A label such as “needs evidence” is not the treatment. Use the evidence taxonomy from `SKILL.md` in notes only; judge recommendations by their premises and strategic fit.

For confirmed factual, numerical, textual, or consistency errors, include the original content, correct content, verification basis, and downstream effects alongside the location. Use the checks in `review-criteria.md`; group minor instances when useful without dropping their locations or corrections. Do not replace a completed verification with “建议核实.”

Surface decisions only when authorization or genuine authorial choice is required. Identify the original content, proposed replacement, what changes, and your recommendation. Do not ask the user to perform the analysis the reviewer can complete. Prior approved choices need not be resubmitted. Enumerated batch approvals are acceptable when each item and its consequence are clear.

## Annotations

Preserve the original wording. Anchor comments to the narrowest relevant location using the same review ID, severity, diagnosis, and treatment. Cover consequential issues rather than annotating every sentence.

Use Word comments where supported, slide notes/callouts that do not obscure the content, or reliable page references for PDF. For pasted text, comments may follow the passage. State any actual format limitation. Never claim an annotated file exists when only review text was produced.

## Clean revision

Return the requested complete report, not selected fragments, an outline, or a future-work plan. Begin from the source architecture and narrative unless a replacement map was approved. Carry forward the report's useful depth, examples, reasoning, and scope. Implement only approved proposition changes and deletions; ordinary meaning-preserving language edits need no separate approval.

Do not place review IDs, evidence-status tags, change rationales, instructions to the author, or reviewer-facing table schemas in the clean draft. Present subject-matter facts, inference, and uncertainty through attribution and ordinary professional language. Material limitations can be legitimate report findings; they are not automatically editorial residue.

If essential support is absent and the requested result cannot be completed, report the exact blocked portion and recommend options. **Do not autonomously deliver an outline, research plan, summary, or review memo in place of the report, even with an accurate label.** Obtain authorization for a different type or scope first. Partial work must be clearly identified and must not be called a completed report. Placeholders are permitted only when the user requests a working draft with placeholders.

Compare source and revision at the level of propositions, scope, examples, qualifiers, and recommendations. Inspect analytical completeness by paragraph group/section according to purpose; do not impose a uniform section template or require every fact paragraph to include an insight. Keep necessary narrative continuity and professional Chinese phrasing.

Extract and inspect all substantive text, including tables, and use the linter for supported formats. Candidate wording matches require context review; a scan's success means only its limited checks found no unreviewed issue. Numbering, actual document layout, natural language, factual support, permission, and preservation remain distinct checks.

## Change comparison and deletion record

When material changes occur, provide a concise comparison with ID, source passage or faithful summary, revised treatment, and reason. Include all critical/major implemented changes; representative language changes are enough. No comparison file is needed for every bounded polish.

When content is deleted, record the exact source location, content removed, disclosed reason/consequence, and user approval for that item or enumerated batch. No approved record means no substantive deletion. A proposition replacement approval covers only the explicitly described replacement, not undisclosed loss elsewhere. A large unexpected length reduction prompts a scope check, not a separate percentage-based approval ceremony or a padding target.

## Summary when requested or useful

Summarize the report's substance rather than the editing process. Match the source's purpose and depth; use “摘要” if a heading is needed. Include the governing conclusion, most consequential findings, and any material qualification. Do not force a fixed finding count, length, action list, or additional summary artifact onto every request.
